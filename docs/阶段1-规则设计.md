# 阶段 1：规则设计文档

## 1. 阶段 1 的定位与约束

### 1.1 核心目标

**做一个 2D 顶视角的"净化+塔防"小玩具**，验证核心循环是否有趣。

### 1.2 技术约束

- **纯 2D 实现**：不涉及 3D 场景、人物模型、AI 寻路等
- **用方块表示所有元素**：地图格子、塔、UI 都用纯色方块/矩形
- **不追求美术表现**：重点是数值和循环，跑通逻辑即可

### 1.3 三大区域在本阶段的简化映射

根据《个人练手三阶段路线图.md》中的三大核心区域，在阶段 1 的 2D Demo 中做如下简化：

**约定：1 回合 = 1 秒，所有"每回合"的描述在实现中按秒计算。**

> 📝 **注意**：此处使用"回合"仅为便于理解的表述方式，实质上游戏是实时运行的，不存在传统意义上的回合制。时间系统基于真实秒数推进，所有系统都在实时更新。
| 完整设想 | 阶段 1 的 2D 映射 | 实现方式 |
|---------|------------------|---------|
| **基地安全区（3D）**<br>- 沙盒式基建<br>- 2D/3D 视角切换<br>- 科技研发 | **内圈安全区**<br>- 用地图内圈几格表示<br>- 作为"资源产出"的数值来源 | - 内圈格子初始污染值 = 0<br>- 每回合自动 +资源<br>- 不做独立基建玩法 |
| **野外危险圈（3D RPG）**<br>- 玩家主控+AI队友<br>- 打怪采集素材<br>- Boss 掉落物 | **外圈污染区 + 压力条**<br>- 用地图外圈表示污染区<br>- 用"压力条/倒计时"模拟野外风险 | - 外圈格子初始污染值高<br>- 全局压力条随时间/污染上升<br>- 压力过高即失败 |
| **塔防场景（2D）**<br>- 独立塔防关卡<br>- 敌人进攻路径 | **反扑事件（简化版）**<br>- 达到净化阈值触发<br>- 暂不做独立场景 | - 净化度到 50%/80% 弹提示<br>- 反扑期间净化效率减半<br>- 持续若干回合后恢复 |

**关键原则**：**本阶段只有一张 2D 地图，基地/野外/塔防都在这张地图上用不同规则体现，不分场景。**

---

## 2. 世界观与核心目标（一句话版）

> 一片被污染侵蚀的区域，玩家作为净化小队指挥官，需要在有限时间内建造净化设施，清除污染并抵御污染反扑，最终收复这片土地。

---

## 3. 核心玩法循环

```
【开局】内圈是安全区（基地），外圈是污染区
    ↓
【建塔】用资源在污染区放置净化塔
    ↓
【净化】时间推移，塔净化附近格子，污染度下降
    ↓
【压力】建在污染格子上的净化塔会随时间被污染腐蚀（耐久下降，直至损坏）
    ↓
【反扑】净化度达到阈值（50%/80%），触发反扑事件
    ↓
【抵御】反扑期间净化变慢，需撑过若干回合
    ↓
【胜利】清理地图所有污染
```

## 4. 地图设定

### 4.1 地图尺寸

- 宽度：`12` 格
- 高度：`12` 格
- 总格子数：144 格

### 4.2 区域划分

**内圈（安全区/基地）**：
- 范围：中心 4×4 区域（16 格）
- 初始污染值：`0`
- 颜色：白色/浅绿色
- 功能：
  - 每回合为玩家提供 `+2` 资源
  - 可选：部分塔只能建在安全区边缘（可不做）

**外圈（污染区）**：
- 范围：安全区外的所有格子（128 格）
- 初始污染值分布：
  - 紧邻安全区：`40–60`
  - 中层：`60–80`
  - 最外层：`80–100`
- 颜色：
  - 污染高（80–100）：深红色
  - 污染中（40–80）：粉红色
  - 污染低（0–40）：浅粉/白色

### 4.3 地图生成规则

初始化时：
1. 中心 4×4 设为安全区（pollution = 0）
2. 其他格子按"到中心的曼哈顿距离"设置污染值：
   - 距离 1–2：pollution = 40–60
   - 距离 3–4：pollution = 60–80
   - 距离 5+：pollution = 80–100
3. 可选：加一点随机波动（±10）避免完全对称

## 5. 塔（净化设施）设定

### 5.1 塔的种类（阶段 1 只做 1–2 种）

| 塔名 | 造价 | 净化范围 | 每回合净化量 | 备注 |
|-----|------|---------|-------------|------|
| **基础净化塔** | 10 资源 | 曼哈顿距离 ≤2 | 每格 -5 污染 | 初始即可建造 |
| **增强净化塔**<br>（可选） | 20 资源 | 曼哈顿距离 ≤3 | 每格 -8 污染 | 可作为后续扩展，阶段 1 可不做 |

**范围说明**：
- 曼哈顿距离 ≤2 = 塔周围形成一个菱形区域（上下左右各 2 格）
- 示例：塔在 (5,5)，则 (5,3)、(5,7)、(3,5)、(7,5) 及更近的格子都在范围内

### 5.2 建塔限制

- 同一格子只能有一座塔
- 只能建在"无污染或污染已部分降低"的格子（可选规则：pollution < 80 才能建塔）
- 资源不足时无法建造

## 6. 资源与经济系统

### 6.1 资源类型

只有一种资源：**建设点数**（或叫"净化资源"）

### 6.2 资源获取

- **起始资源**：`20` 点
- **每回合自动增长**：`+2` 点（来自基地安全区）
- **额外奖励**（可选）：
  - 净化度每提升 25%，一次性奖励 `+10` 点

### 6.3 资源消耗

- 建造基础塔：`-10` 点
- （可选）建造增强塔：`-20` 点

## 7. 回合/时间系统

### 7.1 时间系统

- 1 时间单位 = `1.0` 秒（实时）
- 游戏自动按时间推进，玩家可随时暂停

> 📝 **术语说明**：文档中使用的"回合"概念仅为描述方便，在代码实现中实际使用的是基于秒的时间系统。游戏是连续实时运行的，不是传统回合制游戏。

### 7.2 每回合执行的步骤

```
1. 资源增长：+2 点
2. 遍历所有塔：
   - 对塔范围内的每个格子：pollution -= cleanPower
   - 限制：pollution 最低为 0
3. 更新所有格子颜色（根据新的 pollution 值）
4. 统计全局净化度：
   - 净化度% = (已净化格子数 / 总格子数) × 100
   - 或：净化度% = 100 - (平均污染值)
5. 更新压力条：pressure += 压力增长速率
6. 检查事件触发：
   - 净化度是否跨越阈值（50%/80%）
   - 压力条是否超过上限
7. 检查胜利/失败条件
```

## 8. 塔耐久与腐蚀系统（替代全局压力条）

### 8.1 塔的耐久属性

为每一座净化塔增加耐久度设定：

- **属性**：
  - `maxDurability`：最大耐久（建议初始值：`100`）
  - `durability`：当前耐久（初始 = `maxDurability`）

- **含义**：
  - 塔建在**污染格子**上时，会被污染缓慢腐蚀，耐久随时间下降
  - 塔所在格子的污染值为 0 时，视为安全环境，不再掉耐久

> 约定：耐久变化以「回合」为单位计算，且 1 回合 = 1 秒。

---

### 8.2 耐久与污染区 / 安全区的关系

- **安全区（基地/内圈，pollution = 0）**
  - 建在安全区内的塔：`durability` 不会下降
  - 对玩家来说是“没有压力”的区域

- **污染区（外圈，pollution > 0）**
  - 建在污染区格子上的塔会被持续腐蚀
  - 污染越重，耐久掉得越快

可以按污染等级划分耐久消耗（示例数值，可调）：

| 污染等级 | 条件                     | 每回合耐久消耗 |
|---------|--------------------------|----------------|
| 低污染  | 0 < pollution ≤ 40       | -1             |
| 中污染  | 40 < pollution ≤ 80      | -2             |
| 高污染  | 80 < pollution ≤ 100     | -3             |

伪代码示意：

```csharp
if (cell.pollution > 0) {
    tower.durability -= 1;                 // 基础消耗
    if (cell.pollution > 40) tower.durability -= 1;
    if (cell.pollution > 80) tower.durability -= 1;
}
```

---

### 8.3 塔损坏的判定与效果

- 当 `tower.durability <= 0` 时，判定该塔**损坏**：
  - 该塔不再执行净化效果（不再减少周围格子污染值）
  - 可视化：塔变成“损坏状态”的方块（变灰 / 颜色变暗）
- 玩家仍然可以：
  - **拆除损坏塔**（释放格子），如果需要的话
  - 在有资源的前提下，在其他格子重新建造新塔

> 设计意图：塔在污染区待得越久越危险，玩家需要在“尽快净化”与“塔可能被磨光”之间做取舍。

---

### 8.4 耐久信息的展示（UI 建议）

- 在每座塔上方显示一个小小的耐久条（类似局部压力条）：
  - 绿色 → 黄色 → 红色，对应高 / 中 / 低耐久
  - 耐久为 0 时，显示为空条或特殊损坏图标
- 建在安全区（pollution = 0）的塔：
  - 耐久条保持满格，不再下降，体现“退出污染区就没有压力”的感觉

> 后续如果需要，可以在塔的详细信息中显示具体数值（`durability / maxDurability`），但阶段 1 不强制。

## 9. 事件系统：反扑机制

### 9.1 触发条件

| 事件名 | 触发条件 | 持续时间 |
|--------|---------|---------|
| **第一次反扑** | 净化度从 <50% 首次达到 ≥50% | 10 回合 |
| **第二次反扑**<br>（可选） | 净化度从 <80% 首次达到 ≥80% | 8 回合 |

### 9.2 反扑效果

在反扑期间（`isUnderAttack = true`）：

**选项 A（推荐）**：净化效率减半
- 所有塔的 `cleanPower` 临时 ×0.5

**选项 B**：污染回升
- 每回合随机选 3–5 个格子，pollution +5

**选项 C（组合）**：
- 净化效率 ×0.7
- 压力条增长速度 ×2

可以先选 A 实现，后续根据体验调整。

### 9.3 反扑结束

- 计时器倒数到 0 后：
  - `isUnderAttack = false`
  - 弹出提示："反扑已结束，净化恢复正常"
  - 恢复所有数值

## 10. 胜利与失败条件（塔耐久版本）

### 10.1 胜利条件

本阶段采用更“干净”的胜利判定：

- **唯一胜利条件**：

> 地图内所有格子的污染值 = `0`  
> （即：彻底清除地图内所有污染区域）

实现上等价于：

```csharp
bool IsWin() {
    foreach (var cell in allCells) {
        if (cell.pollution > 0) return false;
    }
    return true;
}
```

> 如果后续测试发现难度过高，可以放宽为 “所有格子 pollution ≤ 5”，但作为目标先按“完全清除”来设计。

---

### 10.2 失败条件

结合“塔耐久”机制，失败的核心逻辑是：  
**净化能力被污染磨光，而玩家已经没有余力重建。**

建议的失败条件：

1. **净化能力彻底丧失**

满足以下条件时立即失败：

- 地图上所有净化塔都已损坏（`durability ≤ 0` 或被拆除）  
- **且** 玩家当前资源 `< 基础净化塔造价`（无法再建一座新的基础塔）

> 含义：没有任何在工作的塔，也没有资源重建，净化行动事实上已经失败。

2. **（可选）长时间无进展**

可选的补充失败条件（如果你后续觉得有必要）：

- 连续 `N` 回合（例如 50 回合）全局净化度没有提升  
  - 且地图上仍有污染格子

可以解释为：净化进程停滞太久，外部形势恶化，被迫撤退。  
阶段 1 可以先不实现这一条，靠“塔全部磨光 + 没资源重建”已经足够形成压力。

---

### 10.3 胜负判断顺序（一回合内）

每回合结算时，建议按以下顺序检查：

1. 先执行塔净化 → 更新格子污染值  
2. 更新塔耐久 → 标记损坏塔  
3. **检查胜利条件**：是否所有格子 pollution = 0  
4. **检查失败条件**：  
   - 是否所有塔损坏且资源不足以重建  
   - （如果启用）是否满足“长时间无进展”条件

> 这样可以保证：即使塔在本回合末尾全部损坏，只要本回合刚好把最后一格净化掉，仍然算玩家胜利。

## 12. 玩家交互流程

### 12.1 建塔流程

1. 玩家点击"建造基础塔"按钮
2. 进入"建塔模式"，鼠标变成塔的图标（或高亮）
3. 点击地图上的某个格子：
   - 检查：是否已有塔 / 资源是否足够 / 是否在允许区域
   - 通过检查：
     - 扣除资源
     - 在该格子实例化塔 prefab
     - 标记 `cell.hasTower = true`
   - 未通过：弹出提示（如"资源不足"）
4. 退出建塔模式

### 12.2 查看信息（可选）

- 鼠标悬停在格子上：
  - 显示当前污染值
  - 显示是否有塔
- 点击已有的塔：
  - 显示塔的范围（高亮周围格子）
  - 显示塔的净化效率

## 14. 未来系统预留（不在阶段 1 实现）

以下内容只作为"设计约束"记录，供后续 3D 阶段参考，**本阶段不实现**：

### 14.1 野外出击与资源消耗

- **完整设想**：
  - 玩家主控角色带队出野外，消耗基地产出的"防护工具"
  - 工具有耐久/次数限制
  - 出击可获得矿物素材、Boss 掉落物
- **阶段 1 映射**：
  - 用"压力条"抽象模拟"野外停留风险"
  - 用"每回合自动资源"抽象模拟"基地产出"

### 14.2 NPC 赠送初始工具

- **完整设想**：
  - 游戏开场，NPC（系统）赠送一个简陋工具
  - 效果：仅能在浅层污染区发现基础矿点
  - 工具残片可回收，加速量产型工具的科技解锁
- **阶段 1 映射**：
  - 可选：前 10 回合净化效率 +10%，文案解释为"初始工具加成"
  - 不做"残片回收"系统

### 14.3 野外污染条与负面效果

- **完整设想**：
  - 在 3D 野外场景中，角色有"污染暴露条"
  - 随深入/停留时间上升
  - 达到阈值触发不同 debuff：
    - 25%：视野变暗
    - 50%：移动减速
    - 75%：持续掉血
    - 100%：强制撤退
  - 工具/科技可降低积累速度
- **阶段 1 映射**：
  - 全局"压力条"达到 100 = 失败
  - 不做分级 debuff

### 14.4 科技树与 Boss 掉落物

- **完整设想**：
  - 基地可研发多条科技线（裂地者科技、碾骨者科技等）
  - 打 Boss 获得特殊掉落物，作为科技树前置素材
  - 残留工具也可加速科技解锁
- **阶段 1 映射**：
  - 只有 3–4 个简单"科技节点"（如：解锁增强塔、净化效率 +20%）
  - 不做 Boss、不做掉落物系统

### 14.5 基地 2D/3D 视角切换

- **完整设想**：
  - 在基地安全区内，可切换 2D 俯视与 3D 第一人称
  - 3D 模式下可以自由走动、查看建筑细节
- **阶段 1 映射**：
  - 全程 2D 俯视，不做 3D 视角

### 14.6 角色系统（战斗干员与工兵）

完整角色设定见 `角色设定.md`，此处仅说明与阶段 1 规则的对应关系：

#### 14.6.1 战斗干员

- **完整设想**：
  - 驻塔加成：减少塔耐久消耗、提升净化效率、使用特殊攻击
  - 组队探索：4人队伍深入污染区打怪、采集、打Boss
  - 污染压力：角色在污染区有独立压力条，消耗基地产品抵御
- **阶段 1 映射**：
  - 塔耐久系统 → 为将来"干员减少塔耐久消耗"预留接口
  - 不实现角色模型、驻塔UI、角色压力条
  - 净化效率 → 已有 `cleanPower` 属性，将来可通过干员加成

#### 14.6.2 工兵

- **完整设想**：
  - 驻塔：加强攻速、伤害、减少攻击间隔
  - 修复塔：消耗基地材料，修复损坏塔的耐久（比重建便宜）
  - 清剿区域：派遣工兵自动清理指定污染区怪物
- **阶段 1 映射**：
  - 塔损坏机制 → 当前只能"拆除重建"，为将来"工兵修复"预留系统
  - 资源消耗 → 当前只有单一"建设点数"，将来扩展为多种材料
  - 不实现工兵派遣、自动清剿等AI行为
